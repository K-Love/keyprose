What this covers

This policy covers the public website at https://keyprose.com. I run that site as Backstage Interactive, a one-person studio. It does not cover backstageinteractive.com, Wild Thesis, or a copy of this software that someone else hosts.

www.keyprose.com redirects to https://keyprose.com. keyprose.app and www.keyprose.app serve this same website. The canonical address for this page is https://keyprose.com/privacy.

Who this is

“I” means Kevin Love. Backstage Interactive is the name of this one-person studio. It is not a team, and this page does not name a separate company. KeyProse does not publish a street address, a phone number, or an email address.

How to reach me

KeyProse does not have its own contact form. For a privacy question, or to ask for a copy or a deletion, use the contact form on the Backstage Interactive homepage (opens in a new tab). In the note, say that it is about KeyProse, and include enough detail for me to recognize the request. That form asks for an email address so I can reply.

This page does not add an email address or a phone number. I do not promise a number of days for a reply.

What you can submit

The site has five tools. Each one sends what you type to this site’s /api as JSON. There is no account. Each tool has a Load Sample button that fills the fields with example text. Those examples are not a real client’s listing.

Listing Writer

The page sends an address, bedrooms, bathrooms, square footage, year built, list price, neighborhood, key features, tone, and length. Sample listing text can use the neighborhood. The live model prompt in this code uses the address, bedrooms, bathrooms, square footage, year built, features, and price. It does not copy the neighborhood into that prompt. The price is in the prompt, with an instruction not to repeat the price in the description.

CMA Assistant

The page sends a subject address, bedrooms, bathrooms, square footage, and comparable sales. Each comparable sale can include an address, sale price, square feet, bedrooms, bathrooms, and a sold date. The estimated value, the range, and the price per square foot are calculated from the prices and sizes you enter. The written summary is sample text, or, when a live call succeeds, text returned by the model. On the public site the PDF is built from that result and placed inside the JSON response. The PDF says it is not an appraisal.

Social Generator

The page sends a property id, tone, platform, and property details: address, bedrooms, bathrooms, square footage, price, and a highlight. The platform choices are Instagram, Facebook, Twitter/X, LinkedIn, or all of them. The tool drafts posts. It does not publish them.

Email Campaigns

The page sends a recipient type, a first name, an agent name, a property address, a price, a highlight, and how many emails to draft. The page script also sends a fixed example of 4 bedrooms, 3 bathrooms, and 2,400 square feet in every email request, even if you did not type those numbers. The tool drafts the emails. It does not send them.

Outreach Engine

The page sends one contact per line, as a name, an email address, and a type, plus a sequence choice and an optional custom note. The result is a preview. The site does not email those contacts.

The built-in sequences (new listing, price drop, open house, and follow-up) are filled from templates on the server. They are not sent to the model. A custom sequence can be sent to the model. That prompt includes names and types for up to five contacts, and the custom note. It does not include the email addresses. The email addresses are still in the request your browser sends to this site’s function.

What the server does with it

The public site is static pages plus a Netlify function at /api/*. The function builds a reply and returns JSON to your browser. The draft stays on that page until you leave or reload. This code does not write the listing, the comps, the contact list, or the generated draft into a database, and it does not save a history of past generations.

There are two ways a reply is made:

  • Sample copy, when no model key is configured, or when a live call is limited, too long, or fails. The page says so when the response includes a notice.
  • A live generation. The function builds a prompt from the fields above and sends it to a chat completions endpoint.

The AI provider

The code reads the key from an environment variable named OPENAI_API_KEY. That name does not mean the provider is OpenAI. The host comes from AI_BASE_URL. If that variable is empty, the code uses https://api.openai.com/v1 and calls /chat/completions on it.

On November 7, 2026, https://keyprose.com/api/health returned ai_mode “live”, host “netlify”, and provider_host “routellm.abacus.ai”. The health check does not return the key. The key configured for that Netlify function is an Abacus RouteLLM key. That fact is from the site configuration. The repository does not contain the key or the saved host. The health check is how the running site shows the host.

The health check does not return a model id. The code uses AI_MODEL if it is set, otherwise OPENAI_MODEL, otherwise gpt-4o-mini. This page does not name the model id on the public site. That setting is not in the repository and is not in the health response.

A live call sends the prompt, a system line on the listing tool, a token cap, and a temperature of 0.7. The code does not send a setting for how long the provider keeps the prompt, and it does not send a setting about model training. I am not stating a retention period or a training rule for the provider.

Abacus publishes its own privacy policy at abacus.ai/privacy-policy (opens in a new tab). That page is theirs. I am not copying it into this policy as a promise about KeyProse. If the host setting changed, the health check would show a different provider_host, and live prompts would go there instead.

When a model call fails, the function writes a short notice that the call failed and then returns sample copy. That notice is not your listing text, and the code does not write the key into it.

What this code saves

The function saves rate-limit counts when a live generation is attempted. It reads an IP address from the Netlify header x-nf-client-connection-ip, or else the first value in x-forwarded-for. It stores a SHA-256 hash of that address, cut to 32 characters, together with the hour, and a count. It also stores one count for the UTC day for the whole site. The store is a Netlify Blobs store named keyprose-ai-limits. The saved value is the count, not your listing.

The defaults in the code are 10 live generations per address each hour and 200 live generations per UTC day for the whole site. Either number can be changed, or turned off, in the host environment. This page does not show the values saved in the Netlify account. It shows the defaults in the code.

The code does not delete old counter keys, and it does not set how long they are kept. If the blob store cannot be opened, the counts stay in memory for that running copy. The function logs that the blob store is unavailable. It does not log your listing in that line.

The public CMA PDF is not saved as a file. It is returned inside the JSON response, and your browser downloads it from that response. The Python server in the repository is not what keyprose.com runs. That server can write a CMA PDF into a temporary directory on the machine that runs it. If you run a copy yourself, you operate that copy.

Your browser

This site’s page code does not set a cookie. It does not use localStorage or sessionStorage. It does not save a history of drafts. When you reload or leave, the draft on the screen is gone unless you copied it. Your browser’s own history can still list the page address. This site’s code does not put the draft there.

A copy button uses your browser’s clipboard. This site does not receive another copy from that step.

The pages use the fonts already on your device. They do not request a font file from Google.

Hosting and logs

Netlify hosts the public site. The repository names Netlify as the host for these pages and for the /api function. When your browser requests a page or calls the API, the host receives the ordinary connection data needed to deliver it, such as an IP address, the page address, the time, and the browser’s user-agent string. This repository does not set how long the host keeps those logs. Netlify’s privacy policy is the host’s own description: netlify.com/privacy (opens in a new tab).

The public address uses HTTPS. This page does not promise encryption at rest. The repository does not describe encryption at rest.

API responses from the function send cache-control: no-store. That header asks caches not to store the JSON reply. It is not a statement about host logs or about the AI provider.

Cookies, analytics, and forms

The pages do not include an analytics script, an advertising pixel, or a cookie banner. Their own code does not set a cookie. I am not describing optional products that can be switched on in a hosting account. Those switches are not in the website files.

The tool fields are not a Netlify Form. Nothing in this code puts them in a form inbox. A tool request is the JSON call described above, used to build the reply.

This code does not sell what you submit, and it does not send it to an advertising network. A live generation does send the prompt to the chat completions host, so that host receives it.

Accounts and payment

There is no sign-in and no payment. The homepage says authentication, billing, and a production database are not included. Using a tool does not create an account and does not charge a card.

How long information stays

A draft on the screen lasts until you reload or leave. This code does not keep a history of it.

Rate-limit counts stay until they are removed. This code does not set a deletion date for them.

This repository does not state how long Netlify keeps logs, or how long the AI provider keeps a prompt. I am not stating a number of days for either one.

Asking for a copy or deletion

Use the contact form on the studio homepage. Say that you want a copy or a deletion, and that the request is about KeyProse. Include the approximate time and which tool you used.

The listing text is not in the rate-limit store. A request about a draft will usually have no saved draft for me to delete from KeyProse. I will say so when that is the case. I cannot describe from this site’s files what copy Netlify or Abacus keeps.

Children

This site is written for adults doing real estate work. It is not directed at children. Do not submit a child’s personal information. The tools do not ask for a child’s age.
